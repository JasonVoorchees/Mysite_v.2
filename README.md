# TREZO

Проект TREZO — Django-приложение с фронтендом на HTML/CSS/JS. В репозитории есть серверная часть (Django, БД) и статические страницы, которые можно опубликовать как статический фронтенд.

## Локальный запуск (Django)

Подробная инструкция находится в файле `ИНСТРУКЦИЯ_ПО_ЗАПУСКУ.txt`.

## Запуск через Docker (основной способ)

### Требования
* Docker Desktop / Docker Engine.
* Docker Compose v2.

### Запуск
```bash
docker compose up --build -d
```

Открывайте сайт на http://localhost:8000/.

### Остановка
```bash
docker compose down
```

### Типичные проблемы
* **Порт занят:** измените проброс порта в `docker-compose.yml` (например, `8080:8000`).
* **Нужно пересобрать:** выполните `docker compose up --build -d`.
* **Нет стилей:** убедитесь, что `collectstatic` не завершился ошибкой в логах `docker compose logs -f web`.

## Deploy via GitHub Pages

> **Важно:** GitHub Pages поддерживает **только статические файлы**. В этом проекте есть серверная логика (Django, БД, аутентификация, API). На GitHub Pages будет работать **только статический фронтенд** — без базы данных, регистрации, авторизации и запросов к серверу.

### Что публикуется

Статический фронтенд готовится из исходников `docs/` и публикуется в каталоге `public/`.
* Точка входа: `public/index.html`.
* Ассеты: `public/css/` и `public/js/`.
* Фолбек для Pages/SPA-роутинга: `public/404.html` (копия главной).

### Шаги включения GitHub Pages

1. Загрузите изменения в ветку `main`.
2. Перейдите в **Settings → Pages**.
3. В разделе **Build and deployment** выберите **GitHub Actions**.
4. Дождитесь завершения workflow `Deploy to GitHub Pages`.
5. Откройте сайт по адресу вида `https://<org>.github.io/<repo>/`.

### Проверка локально

Можно проверить статику любым простым сервером:
```bash
cd docs
python -m http.server 8000
```
Затем откройте `http://localhost:8000/`.

### Настройка базового пути

* Все ссылки и ассеты в `docs/` используют **относительные пути**, поэтому сайт корректно работает как в корне домена, так и в подкаталоге вида `/<repo>/`.
* Если вы меняете структуру файлов, проверьте ссылки на `css/`, `js/` и переходы между страницами.

### Чек-лист деплоя (без 404)

* Убедитесь, что `public/index.html` существует и написан в нижнем регистре.
* В **Settings → Pages** выбран источник **GitHub Actions** (не branch/folder).
* В workflow артефакт указывает на папку `public/`, а внутри артефакта `index.html` лежит в корне (не во вложенной папке).
* Для project pages убедитесь, что ссылки на ассеты остаются относительными (без ведущего `/`).

### Ограничения GitHub Pages

* Не работают: регистрация/логин, сохранение архива, рыночные разделы, сообщения — всё, что требует серверных запросов.
* Для полного функционала нужен запуск Django-сервера и подключение базы данных.

### Чек-лист Docker-запуска

* ✅ `docker compose up --build -d`
* Открыть http://localhost:8000/ и убедиться, что загрузились CSS/JS.
* Проверить страницы `index.html`, `profile.html`, `settings.html`, `archive.html`.
